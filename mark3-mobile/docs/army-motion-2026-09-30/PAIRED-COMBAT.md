# 상대를 향하는 공방으로 교체

이전 구현은 각 병사가 독립된 사인파로 팔을 돌렸다. 적의 위치와 방패의 표면을 표적으로 삼지 않았고, 피격 때 몸 전체를 기울였다. 그 방식의 공격·방어·피격 코드와 독립 불꽃을 제거했다.

## 참고와 적용

- [HEMA 101의 검·버클러 방어 설명](https://www.hema101.com/post/sword-and-buckler-102-i33-part-4-defence): 공격선 사이에 방패를 놓고, 방어 뒤 반격하며 거리를 조절한다.
- [두 사람이 보여 주는 느린 시범](https://video.wixstatic.com/video/9c94ad_e2403809644349888ec4c2f3e3b64187/1080p/mp4/file.mp4): 브라우저 영상에서 두 사람의 마주 선 경계 자세와 방패를 앞세운 접근, 검을 든 공격 준비를 확인했다. 영상 동작을 추출하거나 모션 캡처했다고 주장하지 않는다.
- [Epic의 Motion Warping 설명](https://dev.epicgames.com/documentation/en-us/unreal-engine/motion-warping-in-unreal-engine): 상대 표적에 위치와 방향을 맞추는 원리를 참고했다. 이 프로젝트는 Three.js이며 Unreal 플러그인을 쓰지 않는다.

## 구현

원본 갑옷의 정점에 14개 관절의 가중치를 부여한 SkinnedMesh를 만들었다. 팔과 다리는 두 관절 IK를 사용하고, 검과 방패는 단일 뼈에 연결해 장비가 구부러지지 않는다. 무기를 포함한 전체 경계 상자 대신 인체 중심을 기준으로 어깨 축을 잡았다.

6.4초의 공통 타임라인에서 접근, 공격 준비, 정면 공격, 방패 접촉, 반격, 어깨 피격, 거리 회복을 재생한다. 양쪽 손과 검 끝이 같은 접촉점을 사용한다. 피격 반응과 불꽃은 접촉 후에만 시작한다. 몸 전체를 뒤로 회전시키지 않고, 짧은 상체 비틀림·무릎 굽힘·발 이동을 사용한다.

`?art=1&unit=1`에서 아군/적군 선공, 일시정지, 0.3배 재생, 접촉 순간, 0.08초 전진을 제공한다. 본 게임의 보이는 전투도 동일한 대련 컴포넌트를 사용한다. 1~3쌍을 대표로 보여 주며 마지막 유효타의 주체는 엔진의 승패에 맞춘다. 게임 규칙과 피해 계산은 변경하지 않았다. 전투 연출·결과창 지연은 하나의 7.6초 상수를 공유한다.

## 검사와 한계

`tools/check-army-animation.ts`는 양쪽 선공, 상대를 바라보는 방향, 실제 스키닝된 검 끝과 표적의 오차(3.5cm 미만), 방패 표면 레이캐스트와 충돌점, 접촉 이전 불꽃 금지, 이후 피격 반응, IK 길이 보존을 검사한다. 기존 이동 감지와 시야 비노출 검사도 유지한다. TypeScript 및 11/21 크기 지도 검사를 통과했다.

자동 가중치와 직접 작성한 키포즈를 쓰는 절차적 애니메이션이다. 전문 모션 캡처, 물리 기반 무기 충돌, 모든 병종의 개별 전투 클립은 아니다. 지도 전투는 실제 피해 라운드를 한 타씩 재현하지 않는 대표 공방이다. 원본 장갑의 손가락과 어깨 갑옷은 관절 가중치의 한계가 남는다.
